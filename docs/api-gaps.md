# API gaps — frontend needs vs `backend-spec.md`

Items the frontend needs that the backend spec (v1.0, Oct 2026) does not define precisely.
Each one is mocked behind the RTK Query endpoint it will eventually use (`src/mocks/handlers.ts`),
so switching to the real API only changes the endpoint's `query`/`transformResponse`.

Status: `open` = assumption in code, waiting on backend · `decided` = settled.

| #   | Area  | Need                                                   | What the spec has                                                                                                  | Frontend assumption                                                                                                                                              | Status  |
| --- | ----- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| 1   | Auth  | Forgot password flow                                   | `POST /auth/password/forgot` sends a reset **link** via WhatsApp; `POST /auth/password/reset {token, newPassword}` | Follows the spec: `/forgot-password` (request) → link opens `/reset-password?token=…`. Request body assumed `{phone}`.                                           | decided |
| 2   | Auth  | Student login                                          | §6.1: student code + OTP to guardian or own phone                                                                  | Follows the spec: "طالب" option sends `{studentCode, purpose}`; "ولي أمر" sends `{phone, purpose}` to `POST /auth/otp/request` (spec only lists `phone`).        | open    |
| 3   | Auth  | OTP `purpose` values                                   | `{phone, purpose}` with no enum                                                                                    | `"Login"`                                                                                                                                                        | open    |
| 4   | Auth  | Token response shape (login / otp verify / refresh)    | Prose only ("tokens + profile + permissions")                                                                      | `{accessToken, accessTokenExpiresAt, refreshToken, refreshTokenExpiresAt}` — validated in the BFF (`src/app/api/auth/_lib/bff.ts`); profile comes from `GET /me` | open    |
| 5   | Auth  | `POST /auth/otp/request` response                      | Not specified                                                                                                      | Optional `{resendAfterSeconds, maskedDestination}`; falls back to 60 s and a generic "sent on WhatsApp" message                                                  | open    |
| 6   | Auth  | `GET /me` shape                                        | "profile, tenant, plan, branches, permissions, scope"                                                              | `MeDto` in `src/features/auth/types.ts` (incl. `kind`, `isOwner`, `hidePhones`)                                                                                  | open    |
| 7   | Auth  | `POST /auth/logout` body                               | "revokes refresh token"                                                                                            | BFF sends `{refreshToken}` + `Authorization`                                                                                                                     | open    |
| 8   | Shell | Notifications bell (list, unread count, mark all read) | None; only SignalR `/hubs/dashboard` events                                                                        | `GET /notifications?unreadOnly=&page=`, `GET /notifications/unread-count`, `POST /notifications/read-all`, `POST /notifications/{id}/read`                       | open    |
| 9   | Shell | Global search / command palette (Ctrl+K)               | None                                                                                                               | `GET /search?q=&types=students,groups,payments` → `[{type, id, label, subtitle}]`; falls back to per-module `?search=`                                           | open    |
| 10  | Shell | Active branch                                          | JWT `branch_ids` claim; some endpoints take `branchId` query                                                       | Every backend call sends `X-Branch-Id` (current branch); endpoints that document `branchId` also get the query param                                             | open    |
| 11  | Lists | Idempotency-Key scope                                  | §18: `POST /payments`, `POST /attendance/scan`, `POST /campaigns/{id}/send-now`, `POST /payments/online/intent`    | Header sent on exactly those four (`idempotencyHeaders()` in `src/services/api.ts`)                                                                              | decided |
